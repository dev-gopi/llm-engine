# Repository Audit — 2026-09-21

## Scope

The project ZIP was unpacked and audited against the complete task registry in
[`TASKS.md`](TASKS.md). The audit covered task-ID integrity, task/document
consistency, configuration validity, deterministic fixtures, training/runtime
wiring, and the available automated test suite.

## Verified repository fixes

- Added pytest importlib mode so identically named tests in separate directories
  no longer collide during collection.
- Corrected the reasoning fine-tuning profile (`fused_optimizer` and mixture
  group names) and made QLoRA a true overlay of the base fine-tuning profile.
- Isolated MTP and long-context runtime output/checkpoint/report paths so
  experiments do not overwrite the default run artifacts.
- Wired `mtp_loss_weight` into `Trainer` and the training CLI; MTP auxiliary
  heads now actually participate in training when enabled.
- Stabilized `/proc/stat` CPU monitoring when two reads occur within the same
  kernel tick.
- Added the deterministic governed RSN-002 reasoning SFT seed corpora and
  CTX-002 long-context validation fixtures that the repository documentation
  and tests expect.
- Added the missing multimodal SFT entry to the dataset catalog.
- Made the generated-tokenizer compatibility test skip cleanly when intentionally
  gitignored tokenizer artifacts are absent from a source-only archive.
- Corrected duplicate task IDs: the later Embeddings API entry is `EMB-002` and
  the later Model Health/Readiness entry is `OPS-003`.
- Replaced two undefined task dependencies with existing authoritative task IDs.
- Added `scripts/audit_task_registry.py` plus regression tests so duplicate IDs,
  ID/heading mismatches, and undefined dependencies are automatically detected.
- Converted machine-specific `file:///home/user/...` Markdown links to portable
  repository-relative links throughout the documentation tree.
- Reconciled stale `TODO` statuses where implementation and regression evidence
  already satisfied the local acceptance criteria; external-evidence tasks stay
  `TODO`.

## Important limitation

“COMPLETED” in the registry means the task's repository-level acceptance
criteria are backed by the cited source/tests. It does **not** imply that model
quality, long-context behavior, throughput, multimodal quality, quantized export
quality, or production reliability have been proven without the external runs
explicitly required by the remaining tasks.
